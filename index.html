AI Job Assistant

Asistente de empleo con LLaMA 3.3 70B vía Groq: analiza el encaje CV-oferta, genera planes de aprendizaje y simula entrevistas.

  • FastAPI
  • React
  • Groq
  • LLaMA 3.3
Ver detalles →

Qué es

Una aplicación web que compara tu CV con una oferta de trabajo concreta. Te dice cuánto encajas, qué te falta para el puesto y te ayuda a preparar la entrevista con un chat que conoce tu perfil y la oferta.

Cómo funciona

  1. Entrada. El usuario sube su CV en PDF (o pega el texto) y la oferta. El backend en FastAPI extrae el texto del PDF con pdfplumber.
  2. Análisis. Un prompt de sistema convierte al modelo LLaMA 3.3 70B (vía Groq) en un reclutador técnico que devuelve un JSON estructurado: puntuación de compatibilidad 0-100, skills que coinciden, skills que faltan, puntos fuertes y débiles.
  3. Plan de aprendizaje. Con las skills que faltan, una segunda llamada genera un plan por skill con prioridad, semanas estimadas y recursos (cursos, libros y un proyecto práctico).
  4. Dashboard. El frontend en React + Vite muestra la puntuación, las skills y el plan.
  5. Chat de entrevista. Un chat con el CV y la oferta como contexto que mantiene el historial y permite pedir preguntas probables o una simulación de entrevista.

Organizador documental con IA

Monitoriza carpetas y clasifica documentos automáticamente por su contenido usando Google Gemini y Prompt Engineering.

  • Python
  • Gemini API
  • watchdog
  • PyPDF2
Ver detalles →

Qué es

Un script que vigila una carpeta "bandeja de entrada" y, cada vez que entra un documento, lo lee, decide de qué trata con IA y lo mueve a su carpeta. Sustituye por completo la clasificación manual de archivos.

Cómo funciona

  1. Vigilancia. Con watchdog, un observador escucha los eventos del sistema de archivos y reacciona cuando se crea un .txt o un .pdf en la bandeja.
  2. Lectura. Espera a que el archivo termine de copiarse y extrae su texto. En los PDF lee solo las dos primeras páginas con PyPDF2 para ir rápido.
  3. Clasificación. Envía el texto a Google Gemini con un prompt que obliga a responder con una sola categoría: Facturas, Apuntes o Personal.
  4. Organización. Mueve el archivo a la carpeta de esa categoría, que se crea automáticamente si no existe.

Plataforma gastronómica · TFG

Red social para valorar restaurantes. Full stack con API REST y 42 historias de usuario en Agile. Calificado con 9/10.

  • Spring Boot
  • React
  • PostgreSQL
Ver detalles →

Qué es

Mi Trabajo Fin de Grado (9/10): una red social para descubrir y valorar restaurantes. Los usuarios puntúan, suben fotos, guardan favoritos y siguen a otros usuarios para ver sus recomendaciones. Se desarrolló en Agile con un backlog de 42 historias de usuario.

Cómo funciona

  1. API REST en capas. Spring Boot con controladores, servicios y repositorios para usuarios, restaurantes, valoraciones, favoritos y relaciones entre usuarios, persistida en PostgreSQL con Spring Data JPA.
  2. Seguridad. Spring Security con autenticación por JWT. Todos los endpoints requieren un token, y hay registro, cambio y recuperación de contraseña por email.
  3. Datos reales de restaurantes. Con clientes Feign se consulta OpenStreetMap (Nominatim para geocodificar y Overpass para buscar locales) y se importan restaurantes reales de una zona.
  4. Robustez. Caché, circuit breaker con Resilience4j, validaciones, gestión centralizada de errores, paginación y logs.
  5. Calidad. Documentación con Swagger/OpenAPI, tests de controladores y servicios, fotos almacenadas en Cloudinary y frontend en React.

Credit Risk Scoring En curso

Modelo para predecir el riesgo de impago de un cliente a partir de su historial financiero.

  • Python
  • pandas
  • seaborn
  • scikit-learn
Ver detalles →

Qué es

Un proyecto de scoring crediticio sobre el dataset Give Me Some Credit. El objetivo es estimar la probabilidad de que un cliente tenga un impago grave (más de 90 días de retraso) en los próximos dos años, como hacen los bancos al conceder un crédito.

Cómo funciona

  1. Análisis exploratorio (hecho). Distribución del objetivo (alrededor de un 6-7% de impagos, un desbalanceo moderado), valores ausentes en ingresos y número de dependientes, y detección de outliers y valores imposibles.
  2. Análisis bivariante y correlaciones. Compara cada variable entre clientes que impagan y los que no, y revisa la multicolinealidad.
  3. Control de target leakage. Busca variables sospechosas antes de modelar y deja la imputación dentro del pipeline para no mezclar los datos de entrenamiento con los de test.
  4. Próximos pasos. Feature engineering, modelos de clasificación con pesos por clase y evaluación del scoring.
